# iOS candidate v63 — drop the serial console boot arg

Baseline: v62 (`26008593` source commit; CI `45356410574`, kernel
`45aff1b01f85b1dbe5a77903050005333eb858980cd1118465c3f11f02bda13d`). MAIN only.

## Why

v62 physical boot was definitively rejected: the device stayed on the Apple
logo after console logs, with no lock screen. Read-only symbolication of the
repeated stuck SpringBoard thread placed unslid PC `0x1c2611030` in
`___commpage_gettimeofday_internal+0x350` and LR `0x1c2622b18` in
`_do_compat+0x18c` / `fprintf_stderr+0x2e8`. That is the libsystem stderr /
`write(2)` path, not a lock-screen UI method.

The payload cmdline still contained `serial=3`. In XNU
`osfmk/arm/arm_init.c`, `SERIALMODE_OUTPUT|SERIALMODE_INPUT` enables the serial
console; `fprintf_stderr` writes fd 2 there and can block when nothing drains
the serial console. v63 removes only `serial=3`. All CS, AMFI, code-signing,
trust-cache, page-validation and framebuffer-console mutations remain
byte-identical to v62.

Kernel pstore logging remains active: `a5xelte_log_append()` is called from
`_cnputs()` in `osfmk/console/serial_console.c` before console output selection,
so logs survive without the serial console.

`xnu_target=iphoneos`, `machine_config=M30LTE`, `kernel_config=DEVELOPMENT`.
All build, source-verification, artifact and Cortex-A53 LSE steps passed.

The CI kernel hash changed from v62 because the build is not byte-reproducible
in `__LINKEDIT` metadata: `6c71d45b...` vs v62 `45aff1b0...`. The two kernels

## Physical step

Flash only `shim-boot.img` to BOOT with Heimdall after positive identity and
Download Mode verification. Never flash USERDATA, SYSTEM or RECOVERY; never use
Fastboot. Accept only a persistent visible lock screen plus supporting logs.
Apple logo, console text, process liveness, framebuffer activity and IRT state
are not success.
