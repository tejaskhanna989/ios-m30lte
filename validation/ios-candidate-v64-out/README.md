# iOS candidate v64 — bounded SpringBoard stderr capture

Baseline: v62 source `49e8e046` is the diagnostic source commit (v62 kernel
`45aff1b01f85b1dbe5a77903050005333eb858980cd1118465c3f11f02bda13d`). MAIN only.

## Why

v63 rejected the "serial console blocks stderr" hypothesis: removing `serial=3`
killed both console output and the console→pmsg mirror, leaving a blank screen
with zero `XNU:` pstore records. Deeper read-only symbolication of the v62
`SMP SpringBoard t0` backtrace found VUI media-playback and IKit frames, not
lock-screen code, so symbolication alone cannot identify the fd-2 message.

v64 keeps the v62 kernel policy and `serial=3`, and adds only a bounded
diagnostic: the first 32 writes to fd 2 from `SpringBoard` (`SBERR`) and
`backboardd` (`BBERR`) are copied, at most 190 bytes each, into the existing
`XNU:` pstore ring. This is read-only with respect to userland; no security
state, entitlement, AMFI, signing, trust-cache or page-validation behaviour is
changed.
